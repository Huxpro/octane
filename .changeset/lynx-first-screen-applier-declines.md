Decline a first screen the direct applier cannot finish, instead of faulting the
launch.

A compiled main-thread program that the mount cannot paint — no intrinsic
element factories on the host, a program inside a native list row, a hidden
program — names a page that is perfectly well formed and that the background
renders correctly over the command path. Those three now refuse the first screen
rather than throwing out of `root.render()`: the attempt retires as `skipped`,
the reason is reported as a diagnostic, and the page arrives on the command path.

All three are decided in the applier's pre-walk, which already runs before
anything is created, so a declined page costs zero PAPI calls rather than a
subtree built and torn back out. A program disagreeing with its own plan is the
opposite case and still faults, because no fallback path makes a wrong page
right.
